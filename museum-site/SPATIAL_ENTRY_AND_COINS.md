# Spatial entry and LIVE Coins

The latest Founder request replaces the primary photographic Megapolis with the existing Three.js architectural prototype. Photo files and historical reference records are not deleted.

- The photo city and photo-based Twelve Brand Towns are no longer mounted by Megapolis.
- The renderer no longer creates or loads a city-photo plane behind the doors. Real geometry appears during opening.
- Gold and Silver Coin controls are independent of photographic mode and visible above the scene, including mobile layout constraints.
- Prices remain sourced only from /api/core/prices with its existing polling/visibility/error semantics. Missing/failed prices never become fabricated LIVE values or payable offers.
- Coin details retain units, source status, retry and rules. Opening details blocks scene movement.

This is a procedural architectural prototype, not a photoreal reconstruction or completed production system. Real CORE integration and GPU/browser acceptance must be reported separately.
Local browser acceptance: PASS for gate completion, two visible Coin controls, Gold detail dialog, keyboard movement, mobile 390x844 without horizontal overflow and no JavaScript errors. API responses were deliberately unavailable fixtures, not real LIVE data.
Canvas screenshot sampling: 3,054 distinct colors and 2,918 changed sample points after keyboard movement, confirming a nonblank changing scene. The material pass uses black marble, silver-tone facades and gold/silver mosaic, not the old pale multicolor floor.
Contract suites: spatial-arrival and coin-sky-prices PASS. Public production and GitHub push are not part of these results.
No database, logo, existing House callback, fee rule or payment state was changed.
