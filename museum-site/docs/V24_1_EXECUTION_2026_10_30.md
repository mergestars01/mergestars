## Private House transformations and versions

The optional existing House study now offers Obsidian Palace, Silver Atelier and
Botanical Retreat. Each changes the local roof profile, palette, light, mosaic and
twelve display positions. These are deterministic procedural architectural
studies, not photo-faithful reconstructions or AI generation jobs.

Changes use immutable undo/redo history. Old exported layout JSON remains valid;
the new architecture field is optional and bounded. The common Museum does not
inherit a private room's material or roof changes.

Authenticated GET/POST `/api/house-scenes` and an additive D1 table persist up to
80 immutable private versions per Site visitor. Branching requires an existing
version owned by the same visitor. The server rejects forged owner, CORE,
publication and financial fields. Idempotent retries replay the original result;
changed payloads conflict. Replay still works at the quota. The client retains
request identity after an uncertain save, bounds and validates responses, times
out, and aborts on unmount. Restore keeps the previous layout in Undo history.

Entry paths:
- Grand Museum → optional private spatial study → Edit House layout.
- Existing My Brand Museum → optional private House transformation.

The original Brand Museum remains the default. A saved scene is never presented
as a CORE House, public exhibit, generated model, official order or payment.
The compatibility view now settles the elevator without waiting for unavailable
GPU animation; the timed spatial elevator remains intact.

## Separate commercial calculation module

`lib/commercial-policy.ts` implements strict versioned policy inputs, integer
minor-unit arithmetic, explicit allocation bases, exact sum preservation with
largest remainders, stable key tie-breaking, separate half-up fee rounding and
same-House consolidation. Results include frozen policy/attribution snapshots.

Existing illustrative tables use this module and retain their original example
amounts. Gold/Silver policies have separate identities. No percentage is added to
CORE and no historical settlement is recalculated. Output explicitly cannot
authorize an offer, payment, available commission or production. Tax and final
payable amounts remain pending. This is calculation infrastructure, not a PSP or
live settlement engine.
